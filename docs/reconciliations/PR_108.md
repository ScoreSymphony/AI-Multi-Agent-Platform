# PR #108 stale-branch reconciliation

PR #108 originally carried an early implementation of the Issue #13 data-provider boundaries on `feat/issue-13-data-boundaries`.

Equivalent and newer work reached `main` through PR #85, followed by canonical-ID hardening in #90 and the remaining Issue #13 definition-of-done hardening in #91. The old #108 branch therefore diverged from `main` and could not be merged safely as-is.

## Reconciliation decision

The branch was reconciled by preserving its ancestry while resolving the resulting tree in favor of the current canonical `main` state. Superseded versions of the Issue #13 implementation were not restored.

This specifically preserves the newer canonical behavior already present in `main`, including:

- provider-neutral memory access-policy semantics;
- durable-memory provenance requirements;
- stable platform-owned canonical identifiers;
- canonical provider error mapping;
- current file, memory and knowledge reference implementations and tests.

## Purpose of the reconciled PR

The reconciled PR is history/integration cleanup rather than a second implementation of Issue #13. This note is the only intended net repository change from PR #108 after reconciliation.

Future stale branches should follow the repository reconciliation rules in `CONTRIBUTING.md`: retain current canonical behavior, reapply only still-required unique changes, and never use conflict resolution to reintroduce superseded architecture or tests.
