# Architecture Decision Records

Use ADRs for decisions that materially affect canonical domain models, lifecycle ownership, public contracts, adapter boundaries, persistence ownership, distributed execution, security boundaries or replacement strategy.

Each ADR should record:

- status
- context
- decision
- consequences
- alternatives considered
- affected issues/contracts

Suggested filename: `NNNN-short-decision-title.md`.

Bootstrap intentionally does not create architectural decisions that belong to later numbered issues.
